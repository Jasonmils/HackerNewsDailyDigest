🧭 联系你的知识背景 MikroTik是一种可通过API远程控制的网络设备（路由器/交换机），类似你用代码配置云服务器；LLM能辅助生成并验证复杂的网络配置脚本，降低非专业用户的配置门槛。

  • 变更前后必须 完整备份配置 并放入版本控制，未实际测试过恢复手册的备份等同于无用文件。

  • 当IP冲突导致常规连接失效时，MAC-Telnet 绕过IP层直接在链路层通信，是最后的救命工具。

Running Gemma 4 26B at 5 tokens/sec on a 13-year-old Xeon with no GPU

在 13 年老旧 Xeon 上无 GPU 运行 Gemma 4 26B，速度 5 tokens/秒

▲ 251 分 · neomindryan · 162 评论

作者用一台成本不足 300 美元、13 年前的双路 Ivy Bridge Xeon 服务器，通过修复 ik_llama.cpp 的指令集兼容性问题，使 Gemma 4 26B MoE 模型在纯 CPU 上达到约 5.2 tokens/秒的解码速度，验证了老旧企业硬件低成本运行现代大模型的可行性。

🧭 联系你的知识背景 文中涉及的 AVX1/AVX2/FMA3 代表不同年代的 CPU 向量指令集，决定了量化矩阵乘法的加速路径是否可用；可类比为 GPU 中不同 CUDA 算力版本——旧卡不支持新指令就无法运行优化内核。

  • 双 Xeon E5-2690 v2 (2013 年 Ivy Bridge) 无 GPU 服务器，成本不足 300 美元，运行 Gemma 4 26B MoE 模型，解码约 5.2 tokens/秒。
  • 关键修复：图形生成器在无 AVX2 时仍发出依赖 AVX2 的 MOE_FUSED_UP_GATE 计算，导致未初始化内存输入使输出变成乱码，通过添加标量回退路径解决。
  • AI 助手 Claude 完成了热路径诊断与代码修复，作者仅负责运行实验和验证正确性，展示了人机协作排故的实用性。
  • 混合专家 (MoE) 模型与量化（Q8_0）使得内存带宽受限的老旧 CPU 仍可维持可用的生成速度，适合离线批量任务或 API 后备。

💬 讨论 HN 评论区主要争论本地推理与调用推理 API 的成本：算上电费后本地成本约为 API 的 30 倍，但多数人认为隐私和离线可用性仍是本地部署的核心价值。

Designing APIs for Agents

为 AI Agent 设计 API

▲ 59 分 · benswerd · 31 评论

作者提出面向AI Agent的API设计应放弃人类便利性：消除默认值、拒绝隐式纠错、使用极精确的字段名，让API只提供“事实”（如付款、发消息），而非可本地复现的工具函数。其产品Freestyle据此移除了复杂SDK抽象，以纯指南代替。

🧭 联系你的知识背景 文中Agent指LLM驱动的编码工具（如Claude Code），它们能一次性阅读完整文档并生成数千行代码，因此设计逻辑与为人设计API截然不同。

  • 默认值有害：Agent应显式填入所有字段，隐式默认会增加理解歧义和排查成本。
  • 拒绝隐式纠错：API不应自动修正大小写或接受多义输入，让Agent在错误提示中澄清误解，而非产生不一致代码。
  • 字段名须精确唯一：用`displayName`、`slug`等代替`name`，消除Agent对通用字段的五种不同解读和幻觉。
  • API只需提供事实：核心是完成计费、发消息等不可替代的副作用，任何工具函数均可被AI本地重写，无需封进SDK。

💬 讨论 评论者补充了为Agent提供反馈工具、文本优先接口、批量操作等建议，共识是显式与可调试比简洁更重要。
