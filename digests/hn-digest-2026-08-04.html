Smaller, faster, safer: running Kimi and GLM at scale

更小、更快、更安全：大规模运行 Kimi 和 GLM

▲ 162 分 · ascorbic · 40 评论

Cloudflare 通过 KV 缓存 FP8 量化、GLM 权重 INT4 压缩和共享缓存完整性检查，在不损失准确度的前提下将 Kimi K2.6 的并发上限提升一倍、吞吐达到 2192 tok/s，并使 GLM 解码速度提高最高 55%，大幅降低每 token 成本。

🧭 联系你的知识背景 KV 缓存是 Transformer 推理时为每个 token 存储注意力键值对的内存结构，其大小会随上下文长度线性增长，通常比模型权重更早耗尽 GPU 显存。

  • KV 缓存 BF16→FP8 量化使 Kimi K2.6 可承载上下文从 68.6 万 token 提升至 137 万，并发 64 请求时吞吐 2192 tok/s，超越 BF16 峰值约 41%。
  • GLM 权重 FP8→INT4 压缩将模型体积缩小 40%，解码阶段在低并发下吞吐提升 55%（60→92 tok/s），且各基准测试准确度差异不超过 0.8 个百分点。
  • 分离式 prefill 和 decode 部署允许在不同瓶颈阶段选择最优精度：prefill 继续使用 BF16/FP8 保速度，decode 使用 FP8/INT4 省内存。
  • KV 缓存完整性校验以不到 1% 的吞吐和尾延迟代价避免多请求共享缓存时发生页错乱，默认路径零开销。

💬 讨论 评论区质疑 Cloudflare 未在产品页面标明量化可能误导用户，并指出评测缺少编码类基准，可能掩盖长程任务中的误差累积。
