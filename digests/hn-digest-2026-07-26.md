## 4. [Running a 28.9M parameter LLM on an $8 microcontroller](https://github.com/slvDev/esp32-ai)

**🔑 要点**
- **28.9M参数LLM**运行在约8美元的ESP32-S3微控制器上，完全本地、无需联网。
- 通过**Per-Layer Embeddings**将25M参数存放于慢闪存，仅需取出约450字节/token，速度达9.5 tok/s。
- 对比此前芯片上的260K参数模型，参数量增大**约100倍**，展示了存储与计算解耦的可行性。
- 模型使用**TinyStories**训练，只能生成简单连贯故事，无法执行指令或回答问题。

💬 **讨论**：评论对$5芯片的算力惊叹，并讨论能否将同样技巧用于在CPU+闪存上运行更大模型，以及结合小规模TTS实现离线语音朗读。

## 6. [LLM Usage in Debian: Three Proposals](https://www.debian.org/vote/2026/vote_002)

▲ 102 分 · zdw · [94 评论](https://news.ycombinator.com/item?id=49050859)

📝 **概要**：Debian 项目发起三项关于 LLM 使用的社区投票：提案 A 全面禁止 LLM 辅助贡献，提案 B 在满足法律、质量和披露等条件后允许，提案 C 仅请求避免使用。分歧集中在版权、质量、社区可持续性与伦理，对开源基础设施治理具有风向标意义。

🧭 **联系你的知识背景**：Debian 是 Linux 生态中最稳定、影响最广的基础发行版之一，相当于服务器和开发的“底层 OS 平台”，其贡献政策直接决定大量软件包的代码可信度。

**🔑 要点**
- **提案 A** 彻底禁止 LLM 生成或辅助的代码、文档、翻译进入 Debian，理由是版权不清、质量不可靠、社区文化受损及伦理问题。
- **提案 B** 有条件允许 LLM 贡献，要求工具合同兼容、许可证清楚、贡献者承担全部责任、显著披露使用情况，并禁止向不可信服务发送敏感信息。
- **提案 C** 仅建议贡献者避免使用 LLM，不设强制禁令，但明确反对盲目信任 LLM 输出。
- 提案明确指出 LLM 训料爬取行为实际上对 Debian 基础设施构成**大规模持久 DoS 攻击**，迫使项目启用 JS 验证机制。

💬 **讨论**：评论区争论焦点在于“辅助”定义模糊、禁令可行性不足，但支持者引用 Gentoo 两年前的类似禁令成果，反对者则认为完全禁止不符合 Linux 内核已用 LLM 的现状。

🏷️ `LLM 政策` · `开源治理` · `Debian`

🔥 **回复最多的评论**（simonw · 6 回复）：

>
> Proposal A is "expressly forbid any contributions to Debian written with the use or assistance of large language models (LLMs) or other generative AI tools."
>
> Proposal B is "The Debian project allows AI-assisted contributions (partially or fully generated by an LLM), provided the following conditions are met [...]"

📝 **概要**：Ailin¹ 将 76,636 个 AI 模型协调为一个集体系统，在可验证任务上达到 97% 准确率，远超 GPT-5.5-pro 等单一前沿模型（68–82%）。通过 32 种策略实现多样性推理和完整决策溯源，而非简单路由。

🧭 **联系你的知识背景**：这类似于用集成学习提升预测可靠性，但扩展到数万模型的实时协商，需要理解编排策略如何从分歧中产出更优结果。

**🔑 要点**
- Ailin¹ 协调 **76,636 个 AI 模型**，通过 32 种策略实现集体决策，非多模型路由或 API 网关。
- 在客观可验证任务上精确率达 **97%**，而 GPT-5.5-pro、Claude Opus 4.8 等前沿模型仅 68–82%。
- 系统自动发现、索引和健康检查模型，新模型发布后无需代码变更即可被吸收。
- 每条请求保留完整决策溯源（**ailin_metadata**），包括策略、模型、成本上限和异议信号。

💬 **讨论**：评论者提到模型聚合器容易抄袭表现最好的单一模型，损害多样性；询问 Ailin¹ 如何匿名化并聚合结果以避免这一问题。
