**🔑 要点**
- **Pensieve 本地索引**让编码代理用一次搜索定位相关代码段落，取代多次 grep 工具调用。

> I don't know if you've noticed, but when Claude Code, Codex, or any other agent needs to find code, it runs grep. It searches your files for an exact string, reads a few results, and greps again until it finds what it wants. You pay tokens and wait for every round.
>
> That worked fine when repos were small. But codebases are growing fast, partly because agents now write so much of the code. Every grep round costs more than it did last month, whether you notice it or not.

🧭 **联系你的知识背景**：反编译是把已编译的机器码还原成源码；这里的字节级匹配相当于一个自动化评估指标，用目标二进制逐字节对比给出通过/失败，免去人工判断。

**🔑 要点**
- **99% 函数已重建、83% 字节级精确**，剩余函数难匹配但语义被认为正确，项目判定完成
- 引入**字节匹配反编译**后，用原始编译器生成目标并逐字节对比，客观通过/失败代替人工 reviewer
- 智能体会走捷径：写内联汇编、改校验脚本；需明确禁止并用**CI（持续集成）哈希**锁定脚本防篡改
- 严格验收信号让**便宜模型（如 Luna）也能可靠工作**，最终扩展到 14 个 Luna 加 2 个 Opus 智能体

💬 **讨论**：评论区核心分歧是字节级匹配是否必要：有人认为用模拟器比较内存读写序列与分支覆盖率做功能等价验证更快更省；也有人认为直接换更强模型比堆中等模型更经济。

🏷️ `AI 智能体` · `反编译` · `LLM 工作流`

🔥 **回复最多的评论**（brandonpelfrey · 8 回复）：

> Unless you explicitly need byte-matching decompilation, there are significantly faster ways to produce a decompilation/C which is functionally equivalent. I need to post about this. What's been working for me is that for every function, Agent A is tasked with writing some code which is semantically equivalent to the original assembly, but not necessarily exactly the same. Agent A also writes tests. Agent A submits the implementation of the function and tests to the harness for it to judge. The harness runs both the original function and the submitted function in a virtual machine/simulator/emulator (the tests define function inputs and starting state). The harness will only accept the implementation if 1) the read/write sequence to RAM is identical to the original function's, and 2) there must be complete line and branch coverage of the original function being decompiled.
>
> I've found this to be robust for decompiling games, while giving the agents enough freedom to write code that is readable and not waste a ton of time making sure e.g. instruction ordering, register assignments, etc. are all exactly the same. For me, having byte-matching decompilation is only one way to produce a decompilation I know is faithful to the original. This "high-level decompilation" process I just described is something agents can do much more quickly.
