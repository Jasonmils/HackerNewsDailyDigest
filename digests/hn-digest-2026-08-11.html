Show HN: Needle2: 14MB agentic LLM for phones, wearables, smart home and robots

Show HN: Needle2：用于手机、可穿戴设备、智能家居和机器人的14MB代理型LLM

▲ 185 分 · HenryNdubuaku · 80 评论

Cactus 发布 Needle 2，一个 14MB 二进制的 45M 参数代理型 LLM，仅占 28MB 内存，在 Raspberry Pi 5 上解码速度 500 tok/s，针对设备端工具调用与结构化提取，功耗比同类小模型低 7–85 倍，不依赖 GPU 或 NPU。

🧭 联系你的知识背景 文章涉及的“2位量化”可理解为将模型参数从常见的16位浮点数压缩到2位整数，类似用极少的比特表示权重，使45M参数仅需14MB；而Needle 2在训练时就针对2位量化优化，避免了事后量化导致的性能崩塌。

  • Needle 2 以 45M 参数、14MB 文件大小实现设备端代理型 LLM，单次会话仅需 28MB RAM。
  • 在 Raspberry Pi 5 上达到 500 tok/s 解码，廉价手机 300–700 tok/s，每 token 计算量仅 70 MFLOPs，能耗比多倍低于 LFM2.5 230M 等模型。
  • 将任务限定为工具调用与结构化提取，无需世界知识或散文生成，45M 参数即可在工具调用基准上与 230M+ 参数的 f16 模型互有胜负。
  • 内置置信度评分实现边缘-云协作：低置信度请求自动升级到云端大模型，日常控制保持本地隐私和零延迟。

💬 讨论 HN 评论争议集中在演示效果：部分用户反馈模型对模糊或无关查询产生离谱输出，但普遍认可微调后能在特定设备场景发挥作用，微小模型层级协作方向值得关注。

Humanising LLM Outputs Is Dumb

人性化 LLM 输出是愚蠢的

▲ 160 分 · kuberwastaken · 92 评论

让 LLM 在推理过程中就遵守“人性化”风格要求（如 ASD-STE100 简化技术英语）是一种有损压缩，会悄悄丢弃高价值细节；正确做法是将推理与呈现解耦，只在最终面向人类时才做风格转换。

🧭 联系你的知识背景 ASD-STE100 是一种类似产品规格书的强制简单句式规范，用于消除技术文档的歧义，文中被用作“人性化”风格的典型例子。

  • 对 LLM 施加 ASD-STE100 等风格约束 等同于在推理过程中进行有损压缩，容易掩盖冲突证据、堆栈跟踪等关键失败信号。
  • 代理之间应交换 高保真的结构化数据（原始错误、diff、置信度），而非层层褪化成友好的人话摘要。
  • “对我像对待 ADHD 一样说话”这类流行提示本质是在 错误抽象层 解决问题，正确的落点应是将体裁渲染推迟到呈现边界。

💬 讨论 评论区争议焦点在于 LLM 的思维链（CoT）可能保留原始高保真信息，因此要求模型切换风格未必真的“有损”；但也有评论认为强制风格会引入新的幻觉，且 LLM 训练自啰嗦文本，人性化指令反而可能增加废话。

What's the best programming language for coding agents?

为编程智能体选择哪种编程语言最好？

▲ 68 分 · chaychoong · 56 评论

作者通过自己设计的两项复杂任务（实现 zstd 解码器、复现 Pandoc）发现，之前广泛流传的“动态语言更省 token”结论在简单任务上成立，但在真实复杂任务中消失，甚至静态语言在更高投入下表现更好；小众语言（如 J）表现极差，语言流行度与性能呈正相关，没有哪种语言天然适合 AI 编程代理。

🧭 联系你的知识背景 你可以将 token 理解为 LLM 计费和推理的基本单位，文章在讨论不同语言生成的代码长度（token 数）是否真的影响 AI 编程代理的成本和正确率，以及评测实验设计的陷阱。

  • 此前评测称 Clojure 的 token 数量仅为 C 的 1/2.6，动态语言整体更紧凑，但作者指出那些任务过于简单，结论不具普适性。
  • 在实现 zstd 解码器的复杂任务中，高投入模式下静态语言（如 Rust、Go）的表现反而优于多数动态语言，原“动态语言更高效”的结论被推翻。
  • J 语言在简单任务中极省 token，但在复杂任务中表现接近垫底，AI 代理在冷门语言上缺乏训练数据，性能显著下降。
  • 语言流行度与正确率、成本呈弱到中等正相关，主流语言才是 AI 编程代理的稳妥选择，而非刻意追求高密度语言。

💬 讨论 HN 评论认为 Go 因代码风格一致、工具链快可能是 LLM 使用的好选择，但也质疑用复现已知软件作为评测信号的合理性，更多人期待真实工程中的经验数据。

  • Docker 员工澄清：每个会话是微 VM，拥有独立内核，运行于原生虚拟化层，团队自行编写了 VMM 而非复用 Firecracker。
