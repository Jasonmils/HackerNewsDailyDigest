## 9. [Serve Markdown to AI Agents with Accept Headers](https://acceptmarkdown.com/)

▲ 135 分 · tilt · [79 评论](https://news.ycombinator.com/item?id=49454764)

📝 **概要**：网站可在 HTTP 请求头 Accept: text/markdown 时返回 Markdown 变体，减少 AI 客户端处理的字节数、提高检索信噪比并降低首 token 延迟；但主流 AI 产品尚未采用该头，且 CDN 缓存可能导致格式错配。

🧭 **联系你的知识背景**：Accept 头是 HTTP 客户端告知服务器想要哪种内容格式的机制，类似 API 按请求参数返回不同表示；这里用它换取 AI 客户端更易处理的 Markdown，而不改变现有网页。

**🔑 要点**
- 网站可通过 **Accept: text/markdown** 为 AI 客户端返回 Markdown 变体，省 token、提高检索信噪比并降低延迟。
- 作者提供测试工具检查 URL 是否支持该头、设置 **Vary: Accept** 并在不支持时返回 406。
- 评论援引 Roy Fielding：Accept 头设计不佳，且 Cloudflare CDN 缓存可能返回 **错误格式** 给客户端。
- 评论共识：**主流 AI 聊天机器人尚未采用该头**，网站缺乏投入动力；有人主张客户端转换 HTML 而非重写网页。

💬 **讨论**：评论区普遍认为当前主流 AI 聊天机器人未采用 Accept 头，网站缺乏投入动力；核心分歧在于应由网站原生提供 Markdown，还是由客户端自行将 HTML 转换为 Markdown。

🏷️ `内容协商` · `AI Agent 优化` · `HTTP 缓存`

📝 **概要**：DuckLabs 团队加入 AWS，预计 9 月初生效；DuckDB 等 Duck Stack 组件仍保持 MIT 许可证，由 DuckDB 基金会管理。DuckDB 每日下载量超 100 万，此次收购为商业化实体归属，开源项目本身不变。

🧭 **联系你的知识背景**：DuckDB 是一种嵌入式分析型数据库，可理解为把数据处理引擎打包成像 Python 库一样直接嵌入应用，相当于你在深度学习里熟悉的轻量推理库，但处理的是结构化查询而非神经网络计算。

**🔑 要点**
- **DuckLabs 被 AWS 收购**，团队留驻阿姆斯特丹，交易预计 9 月初完成
- **DuckDB 保持 MIT 开源**，知识产权由非营利 DuckDB 基金会持有
- **每日下载量超 100 万**，显示 DuckDB 开发者采用广泛
- AWS 承诺长期支持开源社区，同时计划开放扩展签名机制

💬 **讨论**：评论区担忧 AWS 未来可能因内部重组而削弱开源投入，但有人指出 DuckDB 知识产权在基金会手中，标题存在误导；另有用户推荐 Apache DataFusion 作为替代。
