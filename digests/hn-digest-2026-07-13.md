## 3. [Claude Code sends 33k tokens before reading the prompt; OpenCode sends 7k](https://systima.ai/blog/claude-code-vs-opencode-token-overhead)
*Claude Code 在读取提示之前发送 33k 令牌；OpenCode 发送 7k*
▲ 495 分 · systima · [279 评论](https://news.ycombinator.com/item?id=48883275)

📝 **概要**：实测显示，Claude Code 每次请求在用户输入前就消耗约 33,000 token 的固定开销，而 OpenCode 仅约 7,000 token。差距来自更庞大的系统提示与工具模式，且 Claude Code 缓存策略效率低、频繁重写，导致实际成本远高于对手。

🧭 **联系你的知识背景**：代理式编码工具通过 API 每次调用都携带系统指令和工具定义，类似模型推理的“前缀”，消耗 token 并影响上下文窗口。

**🔑 要点**
- **Claude Code** 在收到用户指令前固定发送约 33,000 token，OpenCode 仅约 7,000，差距约 4.7 倍。
- **缓存效率**差异巨大：Claude Code 重复写入缓存 token，同任务下比 OpenCode 多出 54 倍，写入缓存按高价计费。
- 引入**子代理**后，父代理的额外自举成本使总 token 消耗膨胀 4.2 倍，一次简单任务从 121k 增至 513k。
- 多步任务时，Claude Code 因**批量工具调用**减少了请求轮次，总 token 消耗反而可能低于序列化的 OpenCode。

💬 **讨论**：社区认为子代理烧 token 最严重，质疑 Anthropic 故意提升 token 消耗以增加收入，部分用户已转向更透明的替代方案。

🏷️ `代理编码工具` · `LLM 成本` · `token 开销` · `Claude Code`

📝 **概要**：通过 mitmproxy 抓包证实：Grok Build CLI 将读取的 .env 密钥等文件内容明文上传，并且无论是否读取，整个仓库（含 git 历史）都会被静默上传至 Google Cloud Storage，12 GB 仓库中 5.1 GB 被传出，是实际模型对话流量的 27,800 倍，且关闭“改进模型”开关无效。

🧭 **联系你的知识背景**：相当于一个 AI 编码助手在未经明确提示的情况下，将你的整个项目目录（包括密钥文件）以及对模型不可见的文件，完整发送到远程云存储。

**🔑 要点**
- **Grok Build CLI 会明文上传被读取文件的内容**，包括 .env 文件中的密钥，直接发送至 xAI 的 API 端点。
- **与读取无关，整个工作区仓库（含 git 历史）都会被上传**，目标为 Google Cloud Storage 桶 `grok-code-session-traces`。

- **关闭“改进模型”设置不影响上传行为**，`/v1/settings` 仍返回 `trace_upload_enabled: true`，上传机制无法在界面中关闭。

## 10. [Old and new apps, via modern coding agents](https://terrytao.wordpress.com/2026/07/11/old-and-new-apps-via-modern-coding-agents/)

**🔑 要点**
