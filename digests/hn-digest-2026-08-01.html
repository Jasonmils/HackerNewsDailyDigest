qm – Multiplayer agent harness for work

qm – 面向工作的多人 agent 运行时

▲ 500 分 · tosh · 107 评论

qm 是一个开源的多用户 AI 助手平台，专为初创公司设计，每个员工拥有独立的工作空间和记忆，同时可在 Slack 和共享频道中协作。它支持多种 agent 运行时（Pi、OpenCode、Claude Code、Codex），通过严格的作用域隔离和安全策略实现企业级部署，避免供应商锁定。

🧭 联系你的知识背景 作用域（scope）类似于为每个员工提供独立的对话房间，内存、文件、权限互不干扰，但又可以加入共享频道协作，解决了将单用户 LLM 助手扩展到公司团队时的上下文污染和安全隔离问题。

  • 支持 Pi、OpenCode、Codex、Claude Code 等多种 agent 运行时，部署不与单一供应商绑定。
  • 每人和每个房间拥有独立的 作用域（内存、文件、权限、沙箱），避免员工间上下文干扰。
  • 提供 Strict（严格审批）/Auto（自动筛选）/Dangerous 三种安全姿态，满足不同企业的安全需求。
  • 通过 qm CLI 初始化组织仓库并部署到自有云账号，支持私有 fork 同步上游，保持核心代码一致。

💬 讨论 评论中多人将 qm 与 Claude Cowork 等产品比较，但多数认同多人 agent 的 scoping 是核心难题，qm 的 per-person scopes 设计被认为直击痛点。

Run Kimi K3 using 29 GB of RAM at 0.50 tok/s

在消费级笔记本上用 29 GB 内存运行 Kimi K3，速度 0.50 tok/s

▲ 181 分 · marcobambini · 72 评论

通过将 2.78 万亿参数 MoE 模型 Kimi K3 的闲置专家按需从 NVMe 磁盘流式读取，WASTE 引擎在 64GB MacBook Pro 上实现 0.5 tok/s 推理，最低仅需 29GB 内存，证明消费级设备运行前沿开源模型已具有可行性。

🧭 联系你的知识背景 MoE（混合专家）模型每个 token 只激活约 4% 的参数，因此可把大部分闲置参数存放在磁盘上按需加载，而非全部驻留内存。

  • Kimi K3 是 2.78 万亿参数 MoE 模型，在消费级笔记本上以 0.5 tok/s 速度运行，首次实现如此大规模模型的本地推理。
  • 引擎 WASTE 用纯 C 编写，零依赖，专家按一次读取流式加载，内存底线仅需 29 GB，推荐 64 GB。
  • 缓存设计极度敏感：36GB 以上缓存可提升命中率，但超过机器物理内存阈值后会导致 OS 换页，性能反而 下降 8 倍。

🧭 联系你的知识背景 “链式思考”指模型在最终答案前生成的中间文本，训练时通过强化学习鼓励产生这些痕迹，但研究表明它们未必是内部计算过程的忠实记录。

  • 东北大学与伯克利 的研究显示，前沿开源推理模型中 30%-60% 的“思考步骤”对最终答案的因果影响极小。

Everyone is building LLM routers, we deprecated ours

大家都在构建 LLM 路由器，我们已弃用自己的

▲ 105 分 · brunaxLorax · 54 评论

Manifest 在 7000 云用户使用 4 个月后废弃了自研 LLM 路由器，结论：大多数场景下，坚持单一经过验证的模型比动态路由更划算，缓存带来的成本节省远大于路由，且路由会破坏行为一致性并增加维护开销。

🧭 联系你的知识背景 如果把 LLM 路由器看作模型选择层，它的失败很像模型评估中追求低推理成本时引入了不可预测的偏差——省下的钱被不一致的行为和调试成本抵消了。

  • 在 7000 云用户中运行 4 个月后，路由带来的省钱效果被一致性和维护成本抵消，最终彻底下线功能。
  • 仅靠提示词无法预判任务复杂度，大量上下文在后续工具调用和网页搜索中才浮现，导致路由决策常常错误。
  • 缓存读取比未缓存输入便宜 75-90%，系统提示和对话历史天然利于前缀缓存，使动态切换模型失去成本优势。
  • 不可预测的模型切换在自动化工作流中引入额外不确定性，评估、系统提示和可观测性维护成本反而更高。

💬 讨论 多数评论认同通用 LLM 路由器难以实用，核心难点在于无法先验判断查询难度；但也有开发者指出，在限定上下文中使用固定模型组合（如分派特定模型给子代理）仍然高效。

AI Visibility Evidence Model: Five Factors, Graded by Evidence

AI 可见性证据模型：五大因素及其证据等级

▲ 5 分 · spetschinka · 0 评论

该模型将影响 AI 生成答案引用率的五因素按证据强度分为 A-D 级。只有主题相关性是 A 级驱动因素，机器可访问是硬性门槛，实体一致性、可提取性和独立验证均缺乏因果证据。模型明确指出 llms.txt、内容重写和自产引用无可靠正向效果，且 60% 以上的带源查询答案存在错误，可见性不等于引用准确性。

🧭 联系你的知识背景 可将 AI 可见性视为“模型在回答时引用某个来源的概率分布”，类似在大量非确定性推理采样中统计某个输入被选中的频率；证据分级如同论文质量评估，A 级有随机对照实验，C 级仅为相关性观察，不可靠的优化技巧类似无效的数据增强。

  • 主题相关性是唯一获 A 级证据的驱动因素，不切题内容几乎不可能被优先引用。
  • 机器可访问是硬性门槛（B 级），但 llms.txt 等文件已被 Google 明确声明不用于搜索或 AI 摘要。
  • 实体一致性和结构化数据可减少歧义，但无因果证据表明其能直接提高 AI 引用率（C 级）。
  • 训练数据中的实体频率有因果作用（B 级），但自产或制造引用无可靠正面证据，且 60% 以上含源查询答案存在事实性错误。
