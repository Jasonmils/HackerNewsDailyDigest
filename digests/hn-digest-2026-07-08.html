Local, CPU-Friendly, High-Quality TTS (Text-to-Speech) with Kokoro

Kokoro 是一个仅 82M 参数的 TTS 模型，支持英文、中文、印地语及约 50 种语音，可在纯 CPU 上生成高质量语音，12 年前的 i7-4770K 仅需 4.7 秒完成一段示例文本。通过容器化部署能提供兼容 OpenAI 语音 API 的服务，适合与本地 LLM 搭配，实现私密、低成本的语音输出。

🧭 联系你的知识背景 Docker 容器类似轻量级虚拟机，可以打包 Kokoro 模型和运行时环境，让你一键启动 TTS 服务器，无需手动配置 Python 依赖或下载模型权重。

  • 82M 参数的 Kokoro 模型在纯 CPU 上实现接近真实的 TTS 质量，无需 GPU，隐私数据不离开本地。

💬 讨论 评论者普遍认可 Kokoro 在小参数下的表现，但指出单字或短词发音不稳定（如“six”变“ah-six-ah”），解决办法是放入长句再通过词级时间戳裁剪出来。

🔥 回复最多的评论 · sudobash1 · 3 回复

I have used Kokoro fairly extensively for an accessibility product. I have loved working with it (especially because I don't have an NVidia GPU like many TTS of similar quality require).

I particularly appreciate the fact that it lets you manually add IPA pronunciation guides. There have been some cases where an important word is a homograph and Kokoro assumed the wrong pronunciation.

The place where it falls a little short is in saying just a single word or two. Try having it say simply "six" and it almost always says something like "ah-six-ah". I found a way around that though. If you give it a longer sentence to say (eg "The word is: six") it will say it fine. The trick is that the Kokoro API gives you the timestamp of each word in the sentence. So you can have a Python script crop out just the word you care about. The intonation is a little flat this way, but is very reliable.

I asked about this on the discord, and was told that it is a limitation of the small parameter size. But in fairness to Kokoro, even eleven-labs' voices suffer from this occasionally.

Pure-Python symbolic regression that rediscovered Kepler's law from 8 data point

纯Python符号回归，从8个数据点重新发现开普勒定律

▲ 10 分 · sade_95 · 6 评论

GP_ELITE 是一个纯 Python（NumPy）的符号回归引擎，无需 Julia 或 C++ 工具链，pip 安装即可用。仅凭太阳系 8 颗行星的距离与周期，3 秒内重新发现了开普勒第三定律（T ∝ a^1.5，R²=1.0），常数优化可达机器精度。内置过拟合防护、离群值鲁棒模式和外推预测，特别适合少量变量的小实验数据，输出可解释公式而非黑盒。

🧭 联系你的知识背景 符号回归不同于你熟悉的深度学习，它直接搜索描述数据的数学公式（如“T = a·√a”），而不是训练权重矩阵。可以类比为自动化的物理定律发现，输出即方程，适合数据太少无法训练神经网络、却需要理解物理关系的场景。

  • GP_ELITE 是纯 Python/NumPy 符号回归引擎，零工具链依赖，pip install 即用。
  • 在只有 8 个数据点时，3 秒内自动推导出开普勒第三定律（T = a·√a），R² 完美等于 1。
  • 内置 Levenberg-Marquardt 常数优化，使库仑定律等公式的常数达到机器精度（1−R² ≈ 8e-32），比 gplearn 的精确恢复率高 27%。
  • 内置鲁棒模式和受保护的外推预测，对电池健康状态（SOH）预测 R²=0.996，且提供 Pareto 复杂度-精度前沿输出。

💬 讨论 HN 评论者主要关心：若同时给半长轴和半短轴会怎样、仅用开普勒时代的 6 颗行星会如何、以及噪声数据下的表现，作者均已回复验证。

First Principles of Model Routing

模型路由的第一性原理

▲ 28 分 · try-working · 12 评论

作者基于构建 role-model 路由器的经验提出三条原则：用差异化模型的二元配对降低路由决策难度；默认保持模型池最小（2个），只在角色明确时扩展；基准测试要用真实负载数据而非仅靠外部评测。

🧭 联系你的知识背景 模型路由类似根据请求难度和约束（成本、速度、质量）动态选择最适合的 AI 模型，如同将不同难度任务分配给不同算力的节点。

  • 不要路由两个能力相近的前沿模型，应组合一个前沿模型和一个在速度/成本/质量上有显著差异的模型，以降低决策难度。
  • 默认只使用2个模型，只有在每个模型有明确差异化角色时才扩大池子，否则只是增加路由决策复杂度。
  • 使用反映真实工作负载的基准测试，而非仅依赖模型元数据或外部评测，以确保路由决策与实际任务匹配。

💬 讨论 评论认为这些并非绝对第一性原理，前沿模型间路由有时能通过“合金效应”提升结果，核心在于清楚每个模型在路由中的具体角色。
