## 3. [Run Kimi K3 using 29 GB of RAM at 0.50 tok/s](https://github.com/sqliteai/waste)

📝 **概要**：通过将 2.78 万亿参数 MoE 模型 Kimi K3 的闲置专家按需从 NVMe 磁盘流式读取，WASTE 引擎在 64GB MacBook Pro 上实现 0.5 tok/s 推理，最低仅需 29GB 内存，证明消费级设备运行前沿开源模型已具有可行性。

🧭 **联系你的知识背景**：MoE（混合专家）模型每个 token 只激活约 4% 的参数，因此可把大部分闲置参数存放在磁盘上按需加载，而非全部驻留内存。

**🔑 要点**
- **Kimi K3** 是 2.78 万亿参数 MoE 模型，在消费级笔记本上以 **0.5 tok/s** 速度运行，首次实现如此大规模模型的本地推理。
- 引擎 **WASTE** 用纯 C 编写，零依赖，专家按一次读取流式加载，内存底线仅需 **29 GB**，推荐 64 GB。

💬 **讨论**：评论区核心分歧在于 0.5 tok/s 是否实用，有人愿意等待简洁回答；同时有人质疑文档和代码是否由 LLM 生成，以及功耗成本与 GPU 集群的差距。

## 6. [Predictive Speculative KV Replication for Bursty LLM Inference](https://jwlabs.vercel.app/post/biting-the-bullet)

📝 **概要**：提出一种预测性推测 KV 缓存复制方法，用流量预测提前将 KV 缓存（保存 Key/Value 状态以复用计算）复制到备用节点，应对 LLM 推理的突发请求潮，减少冷启动延迟并提升吞吐。

🧭 **联系你的知识背景**：KV 缓存是 Transformer 自回归生成时缓存的 Key/Value 矩阵，类似你用过的注意力机制中间结果复用，避免每次重新计算；突发推理指短时间内请求量激增。

**🔑 要点**
- 针对 LLM 推理**突发流量**，用预测模型提前推测热门序列并复制 KV 缓存至空闲节点，避免请求时冷启动
- 方法结合**预测器**（预测即将来的请求序列）与**推测复制**，将 KV 状态预先分发，降低首 token 延迟
- GitHub 开源项目 **bite-the-bullet** 实现了此机制，附有详细手绘风格架构动图
- 方案适合**弹性的生产环境**，能动态平衡缓存新鲜度与冗余度，在突发负载下保持低时延

💬 **讨论**：HN 评论区主要赞美文章中的手绘示意图和高亮动图清晰易懂，未涉及技术分歧。

🧭 **联系你的知识背景**：如果把 LLM 路由器看作模型选择层，它的失败很像模型评估中追求低推理成本时引入了不可预测的偏差——省下的钱被不一致的行为和调试成本抵消了。

**🔑 要点**
- 在 **7000 云用户**中运行 4 个月后，路由带来的省钱效果被一致性和维护成本抵消，最终**彻底下线**功能。
- 仅靠提示词无法预判任务复杂度，大量上下文在后续**工具调用和网页搜索**中才浮现，导致路由决策常常错误。

- 不可预测的模型切换在自动化工作流中引入额外不确定性，**评估、系统提示和可观测性维护成本**反而更高。

💬 **讨论**：多数评论认同通用 LLM 路由器难以实用，核心难点在于无法先验判断查询难度；但也有开发者指出，在限定上下文中使用固定模型组合（如分派特定模型给子代理）仍然高效。

## 8. [AI Visibility Evidence Model: Five Factors, Graded by Evidence](https://www.richresults.ai/evidence.html)
*AI 可见性证据模型：五大因素及其证据等级*
▲ 5 分 · spetschinka · [0 评论](https://news.ycombinator.com/item?id=49130131)

📝 **概要**：该模型将影响 AI 生成答案引用率的五因素按证据强度分为 A-D 级。只有主题相关性是 A 级驱动因素，机器可访问是硬性门槛，实体一致性、可提取性和独立验证均缺乏因果证据。模型明确指出 llms.txt、内容重写和自产引用无可靠正向效果，且 60% 以上的带源查询答案存在错误，可见性不等于引用准确性。

🧭 **联系你的知识背景**：可将 AI 可见性视为“模型在回答时引用某个来源的概率分布”，类似在大量非确定性推理采样中统计某个输入被选中的频率；证据分级如同论文质量评估，A 级有随机对照实验，C 级仅为相关性观察，不可靠的优化技巧类似无效的数据增强。

**🔑 要点**
- **主题相关性**是唯一获 A 级证据的驱动因素，不切题内容几乎不可能被优先引用。
- 机器可访问是硬性门槛（B 级），但 **llms.txt** 等文件已被 Google 明确声明不用于搜索或 AI 摘要。
- 实体一致性和结构化数据可减少歧义，但**无因果证据**表明其能直接提高 AI 引用率（C 级）。
- 训练数据中的实体频率有因果作用（B 级），但**自产或制造引用无可靠正面证据**，且 60% 以上含源查询答案存在事实性错误。

🏷️ `AI 可见性` · `搜索引擎优化` · `证据分级` · `AI 引用`
